## 2. 問題定義
- **核心目標**: 建立一套生產可用的出缺勤管理系統，涵蓋四大功能模組
- **利害關係人需求**:
  - **管理者 (ADMIN)**: 管理員工帳號、部門、查看全公司出勤、設定假別餘額
  - **主管 (MANAGER)**: 審核部屬的請假/加班申請、查看部門出勤
  - **員工 (EMPLOYEE)**: 上下班打卡、申請請假/加班、查看個人出勤與假別餘額
- **技術限制與邊界**:
  - 資料庫限本機 MySQL
  - 前後端分離架構，API 版本化 `/api/v1/`
  - JWT 無狀態認證

## 3. 解決方案探索

### 方案 A: 逐模組漸進式完善（推薦）
- **優點**: 
  - 可依優先級逐步交付
  - 每個模組可獨立測試驗證
  - 風險可控
- **缺點/代價**: 
  - 需要較多的迭代週期

### 方案 B: 一次全部完成再整合
- **優點**: 
  - 一次性交付完整系統
- **缺點/代價**: 
  - 整合風險高
  - 問題排查困難
  - 缺乏早期反饋

## 4. 最終決策路徑
- **選定方案**: 方案 A — 逐模組漸進式完善
- **關鍵理由**:
  1. 現有骨架已完成，需逐步驗證與補完
  2. 優先確保核心打卡功能可用
  3. 再逐步完善權限管理 → 請假/加班 → 代理人
  4. 每個模組完成後立即測試，降低整合風險

### 模組優先順序
| 優先級 | 模組 | 依賴 |
|--------|------|------|
| P0 | 基礎建設（DB 初始化、測試框架） | 無 |
| P1 | 權限管理（Auth + User + Department） | P0 |
| P2 | 員工打卡（Clock In/Out） | P1 |
| P3 | 請假/加班（Leave + Overtime） | P1 |
| P4 | 代理人制度（Agent） | P3 |
